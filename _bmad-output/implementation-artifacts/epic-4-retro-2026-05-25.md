## What went well

- **Stub adapter pattern** kept dev/CI unblocked end-to-end. No real Anthropic billing for any test run, no need for an API key during development, and CI green out of the box. Worth keeping as a default for any LLM-shaped surface.
- **Service-boundary discipline:** `services/llm` does not import from `@healthtracker/validators` or `@healthtracker/api` for production code (snapshot-sync test pins duplicated literals across the boundary). The boundary is operationally meaningful (`services/llm` deploys to Railway, the rest deploys to Vercel) and the code reflects it.
- **Premium gate concentrated** in one middleware (`packages/api/src/middleware/entitlements.ts`). `isPremium` + `premiumProcedure` reusable across `letter.getStatus`, `letter.getForDraw`, `letter.generateBiomarkerSuggestion`, and the worker-side raw-SQL check.
- **Audit-log usage** mature by end of epic: 4 new audit kinds (`letter.queued`, `letter.generated`, `letter.read`, `biomarker_suggestion.generated`), all routed through `writeAuditLog` / `writeAuditLogIfNew`. No inline INSERTs into `audit_log` from this epic's code.
- **Story 4.4 migration discipline:** explicit SQL files for the Drizzle schema deltas, CONCURRENTLY-shaped index swap with `-- supabase: no-transaction` directive, idempotent enum guard. Avoided the `pnpm db:push`-against-prod footgun the Epic 2 retro flagged.
- **Worktree + single-PR stacking:** Stories 4.1 → 4.2 → 4.3 → 4.4 all landed on the same PR branch (`worktree-story-4-1-letter-narrative`) by pushing each story's HEAD onto the existing branch. This avoided 4 separate stacked PRs and kept review context contiguous.

## What hurt

- **Review findings accumulated faster than they were fixed.** Story 4.1's first review surfaced 5 critical/high findings (broken dedup, 23505 tx poisoning, NFR-I3 violation, fire-and-forget IIFE, sequential pg-boss). These weren't applied at the time — Stories 4.2 and 4.3 shipped on top of them. The end-of-epic cleanup commit (`814ff0b`) closed F1–F8 in one go, but by then the underlying schema choices (audit `resource_id = letterId`) had been baked into multiple call sites.
- **The cleanup commit's fixes generated their own HIGH finding** on re-review: F1+F2 reordered the helpers to write audit before letters, but F3's catch-and-continue then allowed an orphan audit row to commit when the subsequent letters INSERT failed. Required a follow-up SAVEPOINT commit (`b092fc9`). Lesson: structural fixes touch invariants the reviewer needs to re-validate; a fix commit deserves the same scrutiny as the original.
- **Test infrastructure gaps surfaced and weren't closed.** No React Native test runner exists for the new mobile screens (LetterReader, biomarker detail). Story 4.2's `failed`-status branch in `renderLetterSlot` is only covered by manual QA. Story 4.4's `migrations.integration.test.ts` (testcontainer-based, AC9 from the spec) was deferred. These deferrals compounded across stories.
- **pg-boss v12 API change cost a typecheck cycle.** `teamSize` was renamed to `localConcurrency`. The existing `services/extraction` consumer didn't use either (default 1), so the change wasn't on anyone's radar. Lesson: when bumping a dep that owns load-bearing semantics (job concurrency, transaction shape), surface the breaking changes in the dep-bump PR description.
- **The dedup index keyed on `letters.id` shipped in Story 4.1 and went undetected for two stories.** Anyone running concurrent enqueues would have seen duplicate letters. This is a strong argument for an integration test that spins up two parallel calls and asserts dedup — Story 4.4's deferred testcontainer would have caught it.
- **Worker-side raw-SQL twin of every Drizzle helper** is a tax. Every change to `packages/api/src/letters.ts:enqueueLetterGeneration` had to be mirrored to `services/extraction/src/notifications/letters-emit.ts`. Snapshot-sync tests catch literal drift but not semantic drift (the F1 dedup bug was semantic). The cost is fundamental to the worker using `postgres-js` directly instead of Drizzle — not solvable in this epic, but worth budgeting for in epics that touch the worker.

## Key learnings

1. **Stuck stories block fixes, not the other way around.** Carry-over findings from Story 4.1 should have blocked 4.2 and 4.3 from being marked `ready-for-dev`. Defer fix → ship next story → defer fix is a doom loop. Next epic: a story's review must close all of its CRITICAL/HIGH findings (or get a recorded exemption) before the next story enters dev.

2. **Re-review the re-review.** The cleanup commit `814ff0b` got reviewed and surfaced an orphan-audit HIGH. The follow-up `b092fc9` got reviewed and was clean. Always re-review a fix commit — fixes are denser per-line in risk than the original code.

3. **SAVEPOINT discipline for nested writes.** When a helper writes multiple related rows inside an outer transaction and the caller wants NFR-I3 (silent skip on failure), the helper MUST run inside a savepoint so the caller's `catch` can roll back the partial write. Both postgres-js (`tx.savepoint(cb)`) and Drizzle (`database.transaction(async (sp) => ...)`) provide this. Worth a CLAUDE.md ops note.

4. **Stub-first LLM development.** The stub adapter let every Story 4.x test run green without an Anthropic key. Future LLM features should ship with the stub first, real adapter second — keeps the dependency surface flat and the integration test cheap.

5. **The architecture's `letterRouter.generate` mutation is mythical.** Architecture docs §9 lines 812–827 show `letterRouter.generate` as the example for `premiumProcedure`. We never built it — generation is event-driven from the upload-confirm tx. The docs should be updated to show `letter.getStatus` as the canonical example.
