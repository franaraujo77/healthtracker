## What Went Well

1. **Deferred work discipline** — 44 deferred items documented across 7 stories, all tracked in `deferred-work.md`. No invisible debt accumulated.
2. **Architectural decisions held up** — The `SET LOCAL` + `protectedProcedure` transaction wrapping (Story 0.4) worked exactly as designed during implementation. No architectural rework required.
3. **CI/CD enforces architecture** — The ESLint no-hardcoded-color rule, drizzle migration check, and accessibility job are active gates, not aspirations. Epic 1 feature work ships against enforced standards.
4. **LGPD/PII scrubbing is genuinely solid** — Four review rounds on Story 0.7 produced recursive, depth-limited scrubbing covering user identity, tags, contexts, breadcrumb data, request bodies, and sensitive headers.
5. **Security review found real issues** — Open redirect (Story 0.3), `doctorProcedure` context leak (Story 0.4), PII scrubbing edge cases (Story 0.7) — all caught in review, not production.
6. **Foundation is feature-ready** — Auth layer, RLS principal model, extraction queue, design tokens, CI/CD, and error tracking are all in place for Epic 1.

---

## Challenges

1. **Security issues caught in review, not design** — Auth, RLS, and PII scrubbing all had security findings surfaced during code review rather than during story planning. Late catches are expensive.
2. **Framework version surprises** — `@tamagui/next-plugin@1.x` incompatible with Next.js 15 (Story 0.2); pg-boss v12 API significantly different from expected v9+ behavior (Story 0.5). Both required mid-story discovery and adaptation. *Accepted as cost of bleeding-edge stack — no action taken.*
3. **RLS test harness has no real assertions** — The adversarial identity test harness (6 identity types) is fully wired with `it.todo()` stubs. CI stays green. This is intentional for Epic 0, but becomes a risk the moment Epic 1 ships the `patients` table.

---

## Key Insights

1. Making deferred work visible (tracked list) is more valuable than minimizing it.
2. Security-critical paths (auth, RLS, PII) need checklist-driven review, not ad-hoc scrutiny.
3. RLS test assertions must ship with the table that introduces the policy — not in a follow-up story.
4. Foundation epics succeed when architectural decisions are stress-tested during implementation. Epic 0's RLS model passing that test is a strong signal for Epic 1.
