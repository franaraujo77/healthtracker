# Story 4.3: Patient taps a biomarker to receive an "Explain this to my doctor" suggestion (Growth)

Status: ready-for-dev

> **Stacks on Stories 4.1 + 4.2 (PR #54).** Reuses the `services/llm` workspace, the Anthropic adapter, the ANVISA system prompt, the `premiumProcedure` middleware, and the `writeAuditLog` discipline that 4.1 landed. This story adds a **synchronous** (non-streaming) LLM path: a single Claude Sonnet call returning a ~50-word pt-BR question the patient can ask their doctor. Surface is a new biomarker detail screen opened from the existing `BiomarkerCard.onPress` (the no-op Story 3.1 left explicitly for 4.3 to wire). **Growth-tier feature** — `premiumProcedure` denies free-tier with an in-screen upgrade prompt.

## Story

**As a** patient,
**I want** to tap any biomarker card and receive a calm, suggested question I can raise with my specialist,
**so that** I can walk into appointments prepared without needing to translate lab jargon myself.

## Acceptance Criteria

1. **AC1 — Tap surface.** Given the patient taps any `BiomarkerCard` in the Início Fingerprint view or the Histórico draw detail, when the detail sheet opens, then a "Pergunte ao seu médico" section is rendered with a single, non-alarmist suggested question in pt-BR generated by the ANVISA-compliant LLM prompt.

2. **AC2 — ANVISA framing in output.** Given the suggestion is generated, when the patient reads it, then it is phrased as a question the patient would ask (e.g. "Posso pedir ao meu endocrinologista para discutirmos o que essa tendência de ferritina significa para mim?") — never as a diagnosis. Regex enforcement: the response MUST NOT match `LETTER_DIAGNOSTIC_PHRASE_REGEX` (already authored in Story 4.1 validators — reuse, do not duplicate). Failed regex match → server returns a generic fallback (`BIOMARKER_SUGGESTION_FALLBACK_PT_BR`) and writes a `biomarker_suggestion.regenerate` audit hint for ops.

3. **AC3 — Premium gate.** Given the `premiumProcedure` middleware is applied to `letter.generateBiomarkerSuggestion`, when a non-premium patient taps the feature, then the mobile detail sheet renders `BIOMARKER_SUGGESTION_PREMIUM_REQUIRED_PT_BR` and the existing `LETTER_PREMIUM_UPGRADE_CTA_PT_BR` upgrade button — the suggestion text is never fetched, never shown.

4. **AC4 — Audit on generation.** Given the LLM call completes successfully, when the suggestion is returned to the client, then `writeAuditLog()` records `biomarker_suggestion.generated` with `actor_id = patientId`, `actor_type = 'patient'`, `resource_id = <loincCode-derived UUIDv5 OR a synthetic correlation UUID>`, `resource_type = 'biomarker_suggestion'`, `metadata = { loincCode, biomarkerName }`. The audit row is written inside the same `protectedProcedure` transaction as the suggestion return — never written when the procedure throws (premium denial, LLM failure).

5. **AC5 — Synchronous (non-streaming) call.** Unlike Story 4.1's SSE Letter, this call returns a single body. Budget: p95 < 3 s end-to-end. The tRPC procedure proxies to a new POST endpoint on `services/llm` (`POST /api/biomarker-suggestion`) — same persistent-server tenant (Railway). Response shape: `{ suggestion: string }`. Anthropic `messages.create` (NOT `messages.stream`) — `max_tokens: 200` is plenty for the target ~50 words.

6. **AC6 — Stub adapter parity.** When `ANTHROPIC_API_KEY` is unset (dev / CI), `services/llm` returns a pt-BR placeholder suggestion via the existing stub adapter shape (mirror Story 4.1 — no real Anthropic billing in CI). Stub returns a known-good suggestion that contains "pode valer a pena discutir" and matches the AC2 regex constraint.

7. **AC7 — Detail-sheet route.** Mobile route: `apps/expo/src/app/biomarcadores/[loincCode].tsx` (Expo Router 6 dynamic). Route params: `loincCode`, `biomarkerName`, `valueNumeric`, `unitUcum` (URL-encoded). The screen renders a header with the biomarker context (using the existing `BiomarkerCard` in `featured` variant if it exists, otherwise plain Text) + the "Pergunte ao seu médico" body + the loading/error/premium-gate states. **Tab bar persists** (UX-DR11) — full-screen modal is NOT used; this is a stack screen with tab bar visible.

8. **AC8 — Cross-tab consistency.** Both Início and Histórico draw-detail BiomarkerCards route through the same `BIOMARKER_DETAIL_ROUTE(loincCode, biomarkerName, valueNumeric, unitUcum)` helper. The route helper lives in `packages/validators` (URL-encodes the biomarker name and unit; Story 3.1 `historicoDrawDetailRoute` pattern).

9. **AC9 — Rate-limiting hint.** A future story will add rate-limiting to the LLM endpoint. Story 4.3 lands an in-memory per-(patientId, loincCode) cooldown on `services/llm` (60 s) so a tap-spam attacker cannot drive Anthropic costs unboundedly. Cooldown hit returns `429 { code: 'COOLDOWN' }`; mobile renders the previously-cached body (state: `useRef`/`useState` cache the last successful response keyed by `loincCode`).

### Patterns to copy (don't reinvent)

- **`services/llm` HTTP route pattern** — `services/llm/src/routes/letter-stream.ts` (Story 4.1). Auth via `verifyJwt(request.headers.authorization)`; 401 on null userId. The biomarker-suggestion route uses the same helper.
- **`premiumProcedure`** (`packages/api/src/middleware/entitlements.ts`) — same import as Story 4.1's `letter.getStatus`. Throws `PRECONDITION_FAILED / PREMIUM_REQUIRED`.
- **`writeAuditLog`** — single sanctioned audit-write path (`packages/api/src/audit.ts`). Use it; no inline INSERTs.
- **Stub adapter parity** — `createStubLLMAdapter` (Story 4.1) returns a known-good placeholder when `ANTHROPIC_API_KEY` is unset. Mirror for `generateBiomarkerSuggestion`.
- **`LETTER_DIAGNOSTIC_PHRASE_REGEX`** (Story 4.1 validators) — Story 4.1 noted this regex was authored but never wired. Story 4.3 wires it as the post-filter for AC2. This closes the "unused constant" code-review finding from Story 4.1 retrospectively.
- **Route helper convention** — Story 3.1's `historicoDrawDetailRoute(collectedAt, labName)` — URL-encode the dynamic params; one helper, two callers. Story 4.3 mirrors with `BIOMARKER_DETAIL_ROUTE`.

### Anti-patterns explicitly forbidden in 4.3

- Do **not** stream this response. AC5 says synchronous; Anthropic `messages.create` (NOT `.stream`).
- Do **not** include LOINC codes or confidence scores in the user-message prompt (architecture enforcement rule 6).
- Do **not** persist suggestion bodies (no `biomarker_suggestions` schema). Audit row only.
- Do **not** wire `BiomarkerCard.onPress` for rows with `loincCode === null` — there's nothing for the LLM to anchor on.
- Do **not** open the detail screen as a fullScreenModal (UX-DR11 — tab bar must persist).
- Do **not** add a parallel premium-required copy; reuse Story 4.1's `LETTER_PREMIUM_UPGRADE_CTA_PT_BR` for the upgrade button.
- Do **not** audit-write inside `services/llm` for this story — the tRPC layer owns the audit (different from Story 4.1's SSE-endpoint-owns-letter.read split). Rationale: the synchronous response is the natural transaction boundary; auditing at the tRPC layer keeps the audit + procedure response atomic.

### Latest tech notes

- **Anthropic `messages.create` (non-streaming)** — returns `{ content: [{ type: 'text', text: string }], usage: {...} }`. Single Sonnet call typically completes in 1–3 s for 50-word outputs. NFR-P2 budget of <3 s first-token applies to the Letter (streaming); the biomarker-suggestion has no NFR-defined budget but a p95 < 3 s target is reasonable for UX.
- **In-memory cooldown** — `Map<string, number>` with periodic GC. Single-process scope (Railway runs `services/llm` as one persistent server; horizontal scaling would need Redis, deferred).
