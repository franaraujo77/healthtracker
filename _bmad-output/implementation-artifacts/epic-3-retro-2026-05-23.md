## 2. What Went Well

### 2.1 The two-round discipline kept finding "shipped invisible" defects

- **3.4 R1-P270 [CRITICAL]** — `shouldPersistQuery` checked `typeof queryKey[0] === 'string'` against tRPC v11 keys that are path _arrays_ (`['observations','getRecord']`). AC5/6/7 were silent no-ops. Caught by reading `@trpc/tanstack-react-query/dist/.../getQueryKeyInternal`.
- **3.3 R2-P263 [HIGH]** — Victory Native `Area` accepts only `y0`; the `y1` prop was silently dropped. The "shaded teal baseline band" filled from `mean − σ` to the _data line_, not `[mean − σ, mean + σ]`. Direct AC1 violation that would have shipped invisible. Switched to `AreaRange`.
- **3.1 R3-P246 [HIGH]** — `new Date('yyyy-mm-dd').toLocaleDateString('pt-BR')` shifted dates back one calendar day for every Brazilian patient. AC1 regression. Birthed `formatCollectedAtPtBr` (now used by 3.3+).

### 2.2 Narrow-catch discipline held across all four stories

**Zero** new `try/catch` blocks in production code. Every defensive guard is explicit (`Number.isNaN`, `Number.isFinite`, `if (high === low)`). The Epic 2 retro Process action #2 is fully internalised.

### 2.3 Append-only validators discipline held

`packages/validators/src/index.ts` grew by ~30 constants across 3.1–3.4. **No prior-epic constant was renamed or mutated.** R3 reviewers grep-verified this every story. The one near-miss (3.1 R2-P244 — Envios CTA copy regression on a file move) was the catalyst.

### 2.4 Single-source render-gating ("dead-code guard" lesson generalised)

Início renders on `recordQuery.data?.drawCount` alone — never re-checks `baselineQuery.data?.baselines.length`. Called out in 3.2 Dev Notes, 3.3 Task 4.9, 3.4 implementation. The Epic 2 dead-code-guard lesson generalised cleanly.

### 2.5 Epic 2 retro prep paid back

The testcontainer integration-test infra (Epic 2 retro Technical Action #1) was actually used: every Epic 3 server-side story shipped an integration test file. Story 3.3's NFR-SC4 load fixture with `NFR_SC4_FULL=1` gating and an `EXPLAIN`-against-named-index assertion (R3-P269) is the strongest test artefact of the epic.

## 3. Challenges

### 3.1 Library-API misuse — a new recurring defect class

Two HIGH/CRITICAL findings (3.3 R2-P263 Victory Native `Area.y1`; 3.4 R1-P270 tRPC v11 query-key shape) were _correct-looking calls to third-party APIs_ that the library silently dropped/ignored. **`context7` was queried for both libraries — and missed both.** The fixes required reading installed `node_modules/.../dist/*` source.

This is the Epic 1 pg-boss v10/v12 column-name bug (Story 1.5 R2-P48) recurring in a new form. **Action item: codify in CLAUDE.md.**

### 3.2 Test-harness debt accumulated to a structural blocker

By Story 3.4 there are **four parallel test gaps**:

- F168 — no vitest+RTL in `packages/ui`
- F168-V — no vitest in `packages/validators` (workaround: tests piggyback on `@healthtracker/api`)
- F168-E / F177 / F178 / F179 — no RTL+expo harness in `apps/expo`

Acknowledged in all four stories; resolved in none. Epic 4's `LetterReader` is the natural forcing function.

### 3.3 Docker-less worktree blocks integration-test execution (F167)

Every Epic 3 server-side story wrote integration tests and deferred running them. The Epic 2 retro's #1 technical-prep item ("land before Story 3.1") landed structurally but execution never happened. **Critical-path item for Epic 4 prep.**

### 3.4 Story 3.4 R2 reversed an R1 dismissal (cross-patient cache leak)

R1's cross-cutting check claimed "cross-patient cache leak (AC6) handled by `invalidateQueries`." R2-P275 read the persist-client source and proved this false: `invalidate ≠ remove`, and persister restore merges into the in-memory cache. Household device sign-out → sign-in could briefly show patient A's Fingerprint to patient B. **Cleanest example yet of "R2 hunts what R1 broke or half-finished."** Lesson: R1 cross-cutting checks deserve the same source-grounded scrutiny as code patches.

### 3.5 Tamagui token escape hatch (new architectural carve-out)

`packages/ui/src/fingerprint-chart-baseline.tsx` hand-resolves 5 Tamagui colour tokens into hex strings with an `eslint-disable no-restricted-syntax` comment, because Victory Native / Skia don't accept `$token` interpolation. First sanctioned hex carve-out since Story 0.2. Spec-sanctioned, documented — but a precedent that could erode discipline if reused carelessly.

### 3.6 Web bundle isolation for Victory Native is fragile

`require("victory-native")` is gated at runtime by `navigator.product === 'ReactNative'`. Verified intact in RN 0.81. Static bundlers (Webpack/Next.js) would still traverse the `require` if `apps/web` ever imported `FingerprintChart` — currently zero web consumers, so the dismissal stands. Future-epic landmine.

## Addendum — Story 3.5 baseline migration (2026-05-27)

**Stories:** 3.5 only. Status: `review` (PR #56 stack, alongside Epic 5's 5.1–5.5).

The Epic 3 retro above was authored on 2026-05-23 with 3.5 still pending. 3.5 then went through **three review rounds** (mirrors the Epic 2 / Epic 3 R3 cadence) and surfaced lessons distinct enough to deserve their own block.

### Delivery summary

| Round | Result                                                                                                                                                                                                                                                                                                                                                                 |
| ----- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R1    | Schema-only `pg_dump --schema=public` from dev DB. Initial decision: pg-boss self-bootstraps.                                                                                                                                                                                                                                                                          |
| R2    | **6 fixes, including a reversed R1 decision**: pg-boss DDL now bundled (343 lines from `getConstructionPlans('pgboss')`) to close the `INSERT INTO pgboss.job` race in the API path. Storage + custom RLS policies concatenated into the baseline (not in `--schema=public` dumps).                                                                                    |
| R3    | **6 fixes**: stripped pg-boss outer `BEGIN;`/`COMMIT;` (Supabase tx-wrap correctness); seeded 4 `pgboss.queue` rows; deduped `consent_grants_revoke_only_revoked_at` trigger (sole source = `custom_rls_consent_grants_zz_revoke.sql`); glob-order rename (`zz` infix) for macOS vs Ubuntu collation parity; pinned `pg-boss` to exact `12.18.2`; .gitignore narrowed. |

Final artifact: `supabase/migrations/0001_baseline_epics_0_to_3.sql` (~1640 lines).

### What Story 3.5 added to the project's muscle memory

1. **`pg_dump --schema=public` does NOT capture `storage.*` policies, `auth.*`, `realtime.*`, role grants, or cluster extensions.** R2 caught this — storage policies for `lab_uploads` were silently missing from the baseline until the dev concatenated `packages/db/policies/custom_storage_lab_uploads_policy.sql` into Section 3. Future migrations replicating the schema-dump approach (Story 5.7's Epic-5 baseline equivalent) must concatenate `custom_*.sql` files explicitly. **Rule:** schema-dump ≠ full re-apply.

2. **Bundling pg-boss schema beats self-bootstrap when the API writes jobs before the worker boots.** R1's recommendation was self-bootstrap (lib owns its migration table); R2 reversed it after spotting `INSERT INTO pgboss.job` calls in `packages/api/src/uploads.ts:123` and `notifications.ts:56` that fire before any worker reads the queue. **Decision rule:** if any tRPC path enqueues without waiting for the worker, bundle the queue DDL; pin the lib version exactly to prevent dependabot drift from the bundled DDL.

3. **Three-tier `IF NOT EXISTS` / DO-block / `OR REPLACE` discipline for idempotent migrations** (R2-#4):
   - Tables / indexes / functions / triggers → standard `IF NOT EXISTS` / `CREATE OR REPLACE` / `DROP IF EXISTS` prefix.
   - Enums + constraints → `DO` blocks guarded by `pg_type` / `pg_constraint` lookups (no `IF NOT EXISTS` form for `CREATE TYPE`).
   - Documented limitation: pg-boss's `job_table_run` helper emits bare partition-table DDL that can't be made idempotent without forking pg-boss. Supabase's per-migration tx-wrap turns this into a retry-from-clean concern; flagged in the baseline header.

4. **Glob ordering across collations is a real bug class.** R3-#5 — `custom_rls_consent_grants.sql` was applied AFTER `custom_rls_consent_grants_revoke.sql` on macOS (default `LC_COLLATE`), and the reverse on Ubuntu/CI. Result: the revoke trigger overwrote the base policy on one platform and not the other. Fix: rename `_revoke` → `_zz_revoke` so lexical order is unambiguous. **Rule for future `custom_*.sql` files that depend on apply order:** use `_zz_` (or numeric prefix) on the dependent file.

5. **Stripping pg-boss's outer `BEGIN;`/`COMMIT;` restored Supabase's per-migration tx-wrap.** R3-#1 — pg-boss's plan file emits its own transaction; Supabase wraps each `supabase/migrations/*.sql` file in a tx already, so the inner pair short-circuited rollback semantics. **Rule:** when bundling third-party DDL into a Supabase migration, strip the third-party `BEGIN;`/`COMMIT;` lines.

6. **`drizzle-kit check` ≠ schema parity.** The check validates the Drizzle migration chain (currently empty → passes trivially); it does NOT compare to the actual deployed schema. The real parity gate is `pnpm db:push` reporting zero changes against the dev DB after applying the baseline. **AC7 is the gate, not `drizzle-kit check`.** Document if 5.7 (Epic-5 baseline) reuses this strategy.

7. **R2 follow-up extended testcontainer setup to apply `custom_rls_*.sql` policy files** (in-scope addition). Closes the gap where the dedup of `consent_grants_revoke_only_revoked_at` (R3-#3) was no longer reachable from any integration test. **Rule:** when a dedup moves a piece of logic from "Drizzle schema" to "custom*rls*\*.sql", the testcontainer setup must learn to load it.
